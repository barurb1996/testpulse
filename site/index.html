Test quality analyser for QA teams

Your tests are green.
Do they check anything?

Testpulse is static analysis for Playwright, Karate and Cucumber suites. It finds tests that pass but verify nothing, and shows which security behaviours your tests never exercise: no 401 test, no 403 test, no test of another user's data. It runs on your machine and needs no changes to your CI.

Tests that pass but verify nothing

The failure mode of AI-generated tests: green, and meaningless.

  • missing, tautological and weak assertions
  • swallowed errors, commented-out assertions
  • 2xx status checked, response never inspected
  • duplicated scenarios, flaky waits
🔒

Security in and around your tests

Hygiene rules plus coverage measured against the spec.

  • hardcoded secrets, disabled TLS, production URLs, real-looking PII
  • missing 401, 403, BOLA/IDOR and input-validation tests per endpoint
  • works for Karate and Playwright API tests
  • SARIF output for GitHub code scanning

FindingWhat happened
Real suites are noisy groundThe first version of several rules produced mostly false positives on Rocket.Chat, Grafana, Superset, Supabase and Karate. We narrowed each rule and recorded the before/after.
AI tests are not empty, they are shallowOf 120 AI-written tests only 7 were slop, almost all "asserts status 200, never looks at the data". The classic tautologies were absent.
The gaps are security testsThe generated suites covered the happy path and many 401s, but most "another user's resource" and invalid-input cases were missing.

These are small samples. Rules were tuned on the same files they were measured on, the labels come from an AI reviewer rather than a person, and the security specs were written for the exercise. Treat the numbers as a regression check, not a benchmark. The full history, including a first run that was wrong, is in docs/VALIDATION.md.

Run it

# analyse a suite (exit code 1 on critical issues)
npx testpulse ./e2e

# only what changed in this branch
npx testpulse ./e2e --changed-since origin/main

# which security tests are missing?
npx testpulse security-coverage ./tests \
  --openapi openapi.yaml --min-coverage 60

# SARIF for GitHub code scanning
npx testpulse ./e2e --format sarif --output testpulse.sarif

In CI

# .github/workflows/quality.yml
- uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- uses: barurb1996/testpulse@v0.2.2
  with:
    path: ./e2e
    project: my-project
    min-score: 60

Node 20 or newer. Quality score drops 10 points per critical issue and 3 per warning. A self-hosted dashboard (history, flaky detection, Slack digests) lives in the same repository.

Privacy

  • Analysis runs locally. Nothing is uploaded unless you pass --push with the address of a server you run yourself.
  • testpulse judge is opt-in and uses your Anthropic API key. Test code is sent only when you run that command, with credentials redacted first.
  • audit-mcp --stdio starts the command you give it on your machine, so only audit servers you would run anyway.
  • The dashboard encrypts stored repo tokens and Slack webhooks, and requires a login. See the security notes for the model and its limits.
